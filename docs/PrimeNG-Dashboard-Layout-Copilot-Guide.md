# PrimeNG Dashboard Layout Copilot Guide## PurposeThis guide defines a consistent PrimeNG-based dashboard layout for the School Portal frontend.## ScopeUse this guide for:- authenticated application shell layout- responsive sidebar + topbar navigation- role-based dashboard landing pages- shared card/grid patterns for Admin, Teacher, Student, and Guardian views## Prerequisites- Angular app in `client/`- PrimeNG + PrimeIcons + PrimeFlex (or equivalent utility classes)- Existing guards and routes:  - `AuthGuard`  - `RoleGuard`## Target Layout Structure- Global shell:  - left sidebar navigation  - top header with app title and user actions  - main content area (`router-outlet`)- Dashboard page content:  - page title and subtitle  - summary cards row  - quick action cards row  - optional recent activity/list panel## Recommended PrimeNG Components- Layout and nav:  - `p-sidebar` (or fixed sidebar block)  - `p-menubar` or custom topbar  - `p-panelMenu` for grouped role menus- Dashboard content:  - `p-card`  - `p-button`  - `p-tag`  - `p-table` for recent activity  - `p-skeleton` for loading states- UX helpers:  - `p-toast` for notifications  - `p-confirmDialog` for sensitive actions## File Targets- `client/src/app/core/layout/app-shell.component.ts`- `client/src/app/core/layout/app-shell.component.html`- `client/src/app/core/layout/app-shell.component.scss`- `client/src/app/features/admin/admin-dashboard/admin-dashboard.component.ts`- `client/src/app/features/teacher/teacher-dashboard/teacher-dashboard.component.ts`- `client/src/app/features/student/student-dashboard/student-dashboard.component.ts`- `client/src/app/features/guardian/guardian-dashboard/guardian-dashboard.component.ts`## App Shell Example (PrimeNG Style)```html<div class="layout-wrapper">  <aside class="layout-sidebar" toggled from topbar.- Ensure main content keeps proper spacing and no overflow clipping.- Use semantic headings and keyboard-focusable controls.## Role Menu Model Guidance- Build menu items from primary role in `AppShellComponent`.- Keep route labels aligned with existing modules.- Always include a top `Dashboard` item for the role root route.## Styling Guidelines- Use CSS variables for colors and spacing.- Keep card spacing consistent (`16px` or `1rem` baseline).- Prefer subtle elevation (`box-shadow`) and rounded corners.- Keep text contrast AA-compliant.## Accessibility Checklist- Sidebar toggle has accessible label.- Buttons use visible text or `aria-label` with icon-only actions.- Heading hierarchy is logical (`h1` in shell, `h2` in dashboard sections).- Focus states remain visible.## Implementation Checklist- [ ] PrimeNG layout components added to shell- [ ] responsive sidebar behavior implemented- [ ] role-based menu model renders correct links- [ ] dashboard pages use unified `p-card` grid pattern- [ ] loading and empty states added where needed- [ ] unauthorized and not-found routes remain reachable## Verification Steps1. Log in as each role and confirm dashboard renders with sidebar + topbar.2. Test on mobile width and verify sidebar toggle works.3. Open every dashboard quick action link and verify target route exists.4. Verify refresh on `/admin`, `/teacher`, `/student`, `/guardian` still loads.5. Confirm no console errors for missing PrimeNG imports.## Notes for Copilot PromptsWhen asking Copilot to implement UI from this guide, include:- target role (`ADMIN`, `TEACHER`, `STUDENT`, `GUARDIAN`)- exact file to edit- required PrimeNG components- expected route links- responsive requirement (`desktop + mobile`)## Last Updated- 2026-05-12
